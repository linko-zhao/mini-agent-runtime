任务 A · 定义 ToolDefinition 与可选绑定接口

15 MIN

internal/model/model.gointernal/tool/tool.go保留 Day 01 的 Model.Generate(ctx, messages) 签名，避免影响 Mock Model。通过可选接口为支持工具的 Provider 增加能力。

// internal/model/model.go
// ToolDefinition 是 Runtime 统一的工具描述，不包含执行函数。
type ToolDefinition struct {
    Name        string          // 工具唯一名称，如 calculator
    Description string          // 帮助模型判断何时调用该工具
    Parameters  json.RawMessage // 工具输入的 JSON Schema 对象
}

// ToolBinder 由支持 Tool Calling 的模型适配器选择性实现。
// 返回绑定后的 Model，避免修改共享 Adapter 的内部状态。
type ToolBinder interface {
    WithTools(defs []ToolDefinition) (Model, error)
}

// internal/tool/tool.go
// DescribedTool 是可选能力，不破坏 Day 01 的 Tool 接口。
type DescribedTool interface {
    Tool
    Definition() model.ToolDefinition
}

边界：定义在 model 包中，Provider 不依赖 tool 包；tool 可依赖 model 的纯数据类型。保留原有 Mock Tool，必要时仅为真实 Provider 的工具增加 Definition()。

任务 B · 为 Calculator 提供工具元数据

20 MIN

internal/tool/calculator.go沿用 Day 01 的 Calculator 工具，补充 Definition()。本日用 a、b 两个整数作为参数，不执行任意表达式或系统命令。

// 仅示例工具元数据；保留你已有的 Execute 实现。
func (c *Calculator) Definition() model.ToolDefinition {
    return model.ToolDefinition{
        Name:        "calculator",
        Description: "计算两个整数的和",
        Parameters: json.RawMessage(`{
            "type": "object",
            "properties": {
                "a": {"type": "integer"},
                "b": {"type": "integer"}
            },
            "required": ["a", "b"],
            "additionalProperties": false
        }`),
    }
}

实现要求：Definition().Name 与 Name() 一致；重复工具名称应在组装 Agent 时拒绝；至少检查 Parameters 是合法的 JSON 对象。今天不实现完整的 JSON Schema 校验器，它属于第二周的 Tool Infrastructure。

任务 C · Adapter 实现 Tool Binding 并序列化请求

30 MIN

internal/model/openai/adapter.gointernal/model/openai/convert.go为 Day 02 的 HTTP Adapter 实现 model.ToolBinder：将绑定的定义转成 Chat Completions 请求体中的 tools，每轮 Generate 都携带可用工具列表。

// 关键形状：以下为 Provider 请求 JSON 片段，不是完整 Go 实现。
{
  "tools": [{
    "type": "function",
    "function": {
      "name": "calculator",
      "description": "计算两个整数的和",
      "parameters": {
        "type": "object",
        "properties": {
          "a": {"type": "integer"},
          "b": {"type": "integer"}
        },
        "required": ["a", "b"],
        "additionalProperties": false
      }
    }
  }]
}

关键点： Parameters 应作为 JSON 对象发送，不能被二次编码成字符串。WithTools 建议返回拷贝后的 Adapter；不要在共享实例上直接追加可变的工具列表。Day 02 的 ToolCall.ID 与 Arguments 转换逻辑保持不变。

任务 D · 在 Agent 初始化阶段连接 Tool 与 Model

15 MIN

internal/agent/agent.gocmd/demo/main.go从已注册工具中提取 ToolDefinition，通过类型断言判断模型是否实现 ToolBinder，绑定后再进入既有 Run 循环。

最小约束：真实 HTTP Adapter 必须能获得工具定义；Mock Model 可以继续使用预设 ToolCall，不强制实现 ToolBinder。如真实 Provider 缺少工具绑定能力，应在初始化阶段报错，而不是运行时静默丢弃工具。

工程建议：在 Agent 构造或配置阶段完成一次绑定；不要每个 Loop Step 重新修改 Adapter。工具注册表初始化后先视为只读，以免引入并发数据竞争。

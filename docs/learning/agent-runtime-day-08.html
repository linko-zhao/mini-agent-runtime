Go 练习与设计任务

20 分钟 · 建立工具契约

建议练习目录 labs/week02/day08/（新建独立 Go module，也可自行选择练习目录）。在 tool.go 定义描述、调用、结果，明确 name、description、input schema、call ID 的归属。设计 Meta(ctx) 与 Invoke(ctx,args) 两个接口；描述对象不存凭据，调用 context 传递取消与请求范围信息。

// 教学设计，不要求与 Eino API 完全相同
type Spec struct {
    Name, Description string
    InputSchema json.RawMessage
}
type Described interface { Meta(context.Context) (Spec, error) }
type Invokable interface {
    Described
    Invoke(context.Context, json.RawMessage) (string, error)
}
type Call struct {
    ID, Name string
    Arguments json.RawMessage
}

20 分钟 · 注册与向模型暴露

在 registry.go 实现 Register、Lookup、Specs。注册时拒绝空名与重复名；Specs 返回确定性顺序的描述副本。分开“Runtime 已注册的能力”与“本轮模型可见的工具集合”；过滤可见集合不等于完成执行授权。模型绑定接收描述，不持有执行函数。

25 分钟 · 两种有实际意义的工具适配

在 tools.go 设计 SearchKnowledge 和 GetDocument：前者按 query 返回文档 ID/摘要，后者按 ID 返回文档正文。通过注入的 Store 接口调用外部能力，练习时用内存 FakeStore。说明鉴权、超时、结果大小限制分别归业务适配层还是 Runtime；参数解析只占少量时间，不钻进具体业务算法。

15 分钟 · 对照 Eino 做设计说明

在 design.md 列出自研 Spec/Meta/Invoke 与 Eino ToolInfo/Info/InvokableRun 的映射；说明为什么不直接把所有函数暴露给模型，以及哪些能力适合后续流式工具或 MCP 适配。写出调用流程，不要求接入真实 LLM 或联网服务。

20 分钟 · 对齐工具契约

阅读 examples/internal/tool/contract.go。Spec{Name, Description, InputSchema} 描述模型可选能力；Described.Meta(ctx) 只提供元信息；Invokable.Invoke(ctx,args) 执行调用。Call 复用 model.ToolCall，因此 ID、Name 和原始 JSON 参数沿用既有消息契约。通过 Adapt 将新接口适配为旧 Tool/DescribedTool，Agent Loop 不必更换调用协议。

// examples/internal/tool/contract.go
type Spec struct {
    Name, Description string
    InputSchema json.RawMessage
}
type Described interface {
    Meta(context.Context) (Spec, error)
}
type Invokable interface {
    Described
    Invoke(context.Context, json.RawMessage) (string, error)
}
// Call 复用既有 model.ToolCall；Adapt 兼容已有 Tool.Execute。

20 分钟 · 注册与本轮模型可见集合

阅读 examples/internal/tool/registry.go 和 examples/internal/agent/options.go。Register 在入口拒绝空名、重复名及非法 schema；Specs 稳定排序并返回副本，不执行工具。Registry.Tools() 把注册集合适配给既有 agent.New；WithVisibleTools 只控制发给 ModelBinder 的描述集合，运行时仍保留注册能力，不能把“模型看得见”当成授权。

25 分钟 · 通过 Store 适配实际能力

阅读 examples/internal/tool/knowledge/tools.go：SearchKnowledge 按 query 返回 ID/摘要，GetDocument 按 ID 读取正文。两者通过注入的 Store 调用后端，凭据留在 Store 适配层；Runtime 传递执行 context。FakeStore 和 examples/cmd/knowledge/main.go 展示离线的“检索 → 读取 → 模型总结”往返。当前 FakeStore 不提供生产鉴权；执行授权由后续课程设计。

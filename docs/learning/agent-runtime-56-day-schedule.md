# Agent Runtime · 56 天定时学习任务

## 任务说明

每天生成当天的一份 Agent Runtime 学习计划，覆盖连续 8 周（Day 01–56），到 Day 56 后停止并提示进行综合复盘；禁止自动从 Day 01 重新循环。每周第 7 天用于集成、回归与复盘，同时仍生成当天独立的 HTML 学习文档。

## 教学目标与引导规范（每次生成必须遵守）

本实战计划的首要目标是帮助学习者弄懂 Agent 的搭建思路：面对需求，能识别问题、划分职责、设计数据流、解释取舍，并能在需求变化时判断应修改哪一层。编码、源码阅读和测试用于验证这些判断。不得只罗列接口、文件、命令和时间安排。

每份计划按以下顺序提供可独立理解的引导：

1. **为什么学今天的内容**：承接已有能力，用一个具体需求说明当前设计遇到的问题，指出本日新增能力在完整 Agent 中的位置。先解释概念，再引入接口名称。
2. **先走通完整过程**：用同一个场景画出组件关系与运行数据流，明确谁产生/消费输入输出、控制权如何转移、结果如何进入下一轮模型。区分装配阶段与运行阶段；说明 Mock 能验证什么，真实模型行为还需要什么证据。
3. **为什么这样设计**：对主要抽象说明它解决的问题、直接做法会带来的局限、分层选择及代价。不为抽象而抽象；业务示例只服务于理解 Agent 架构。
4. **带着问题读源码**：每段官方阅读给出待回答的问题、定位符号、预期理解与自研映射，避免只要求“阅读文件”。保留 20 分钟阅读、80 分钟编码、20 分钟测试复盘的时间分配。
5. **每项练习自带引导**：在任务本身写明“为什么做 → 操作与观察 → 完成证据”，注明文件是新增、修改还是复用；让学习者仅看学习安排就明白目的。已有参考实现时，先自行画设计/预测行为，再对照实现，无需无意义地重建同名文件。
6. **验收搭建思路**：测试断言对应设计不变量；复盘至少包括一次不看代码讲解数据流、一次需求变化推演（增加能力/替换实现/改变策略时改哪层）。分别列出理解验收与实作验收，不能把测试通过或清单勾完等同于理解。
7. **解释次日衔接**：说明今天解决了什么、还剩下什么问题，以及为什么下一天的主题自然承接。每页独立可读；避免把生成流程说明挤占核心教学内容。

生成后自查：只看任务安排，学习者能否回答“为什么做、在整个 Agent 中起什么作用、如何判断理解了”？任一答案缺失则先补齐引导再交付。

## 每次执行

1. 从任务状态取得当前日序号 `XX`（两位数，01–56）。以任务保存的开始日期和时区计算日期；若无法确定日期或日序号，说明阻塞原因并请求修正任务状态，不猜测、不重复生成其他日。
2. 检查 `docs/learning/agent-runtime-day-XX.html` 是否已存在，并先读取前一天文档（若存在）；优先沿用已有文档的深蓝头部、白色卡片、字体、颜色及响应式视觉风格。依据课程路线与概念依赖安排当天内容，不读取当前工程的 Go 实现或测试来选择课题；不以任何前一天编码完成、合并或修复缺陷作为课程发布门禁。
3. 生成一份**完整、独立、UTF-8、离线可读、移动端响应式**的中文 HTML。目标路径：`docs/learning/agent-runtime-day-XX.html`。不得依赖 CDN、外链脚本、字体或样式。可引用官方资料链接，但文档内容本身必须独立可读。
4. 每份计划均包含：20 分钟官方源码/文档阅读（提供可访问链接和具体阅读目标）；80 分钟 Go 编码任务（明确文件路径、接口/数据流、步骤、边界和任务时间分配）；20 分钟测试与复盘（具体命令和验收条件）；localStorage 保存的可勾选清单与自动进度条；目标、Definition of Done、风险或前置门禁、复盘问题及次日衔接。测试命令与断言作为连续课程示例的建议验收（验收独立于实际项目完成状态），不依赖当前工程工作流；标注尚未执行，不伪称通过。每份计划持续结合 Eino 官方源码，提供准确路径、符号、阅读目标及自研设计映射。以 Agent Runtime 的抽象、数据流和执行策略为主线；业务工具仅用于说明，不围绕 calculator 等示例展开连续的修补任务。
5. 学习路线按顺序推进：
   - 第 1 周（01–07）：Runtime 基础、Model 接口、Agent Loop；Day 07 集成复盘。
   - 第 2 周（08–14）：Tools、工具协议、MCP；Day 14 集成复盘。
   - 第 3 周（15–21）：状态机、运行状态、Checkpoint；Day 21 集成复盘。
   - 第 4 周（22–28）：中断、审批、人机协作、故障恢复；Day 28 集成复盘。
   - 第 5 周（29–35）：Context 管理、压缩、Memory；Day 35 集成复盘。
   - 第 6 周（36–42）：调度、并发、隔离与资源边界；Day 42 集成复盘。
   - 第 7 周（43–49）：Tracing、可观测性、评估与回归；Day 49 集成复盘。
   - 第 8 周（50–56）：部署、可靠性、综合集成和最终验收；Day 56 完成后提示综合复盘并结束任务。
6. 如仓库支持 GitHub 写入且凭据可用，先确认目标仓库 `linko-zhao/mini-agent-runtime` 的 `main` 分支和目标路径。先读取同名文件及其当前 SHA；文件不存在则创建，已存在时先比较内容，仅确需更新才基于刚读取的 SHA 安全更新。同时更新根目录 index.html 的当天入口并保留周模块，内部路由使用 docs/learning/agent-runtime-day-XX.html 相对路径；当天 HTML 与 index.html 均提交到 main 并回读确认，不修改 Go 源码或创建/合并 PR。提交信息严格使用 `docs(learning): add day XX agent runtime plan`。提交后确认分支、路径和提交结果；在当日回复同时提供 GitHub 文件链接和可下载 HTML 链接。
7. 若没有 GitHub 连接权限、工具不支持上传文件内容、SHA 冲突或提交失败，不得声称已提交；解释实际失败原因，并仍提供已生成 HTML 的可下载文件或完整结构化学习任务。任何不确定状态都不得通过覆盖其他文件来绕过。

## 任务结束条件

Day 56 生成并完成适用的验证与交付后，发出综合复盘提醒并停止任务，不安排 Day 57，也不重新开始新一轮。

## 第 2 周课程细化与后续教学原则

- Day 08：Agent Tool 抽象；结合 Eino BaseTool、InvokableTool、StreamableTool，设计描述、执行与注册边界。
- Day 09：Agent Tool 执行器；结合 Eino ToolsNode，设计批次校验、调用 ID 关联、错误策略与 Loop 消息往返。
- Day 10：工具执行策略与 Eino 中间件；超时、取消、重试资格、幂等和结果预算。
- Day 11：工具可见性与执行授权、只读/写入能力边界、审计；以检索和外部业务 API 为例。
- Day 12：MCP Client/Server、初始化与能力协商、tools/list 和 tools/call；区分协议与 Agent 执行策略。
- Day 13：MCP 到本地 Tool 抽象的适配；复用注册、调用关联、取消和错误语义，不复制业务工具实现。
- Day 14：模型 → 工具/MCP → 结果 → 模型的综合集成与复盘。

后续各周继续遵循原定主题与 Eino 源码对照。每天按课程顺序发布，实际项目进展由学习者自行消化，不触发补课循环或阻止后续页面生成。练习目录、接口、模块和命令均明确标记为建议设计，不陈述为当前工程事实。

## 示例代码连续性（每次生成必须遵守）

示例代码必须与已发布学习计划保持结构连续性：生成前读取前一天及相关基础章节中的代码示例，整理已有模块路径、目录/包、类型、接口签名、构造函数、消息结构、错误语义及数据流；在这些约定上增量扩展，复用既有定义，不另起每日独立module或无说明更换命名/结构。以学习文档中的设计为依据，不扫描实际工程源码来选题或判断完成情况。若前序示例存在设计冲突，优先沿用最早建立且后续章节依赖的契约，并显式说明差异；确需变更时，在当页给出旧接口→新接口的对应、修改文件、调用方调整及完整迁移步骤，区分新增/修改/复用代码，保证累计示例可以组合。每天包含“承接前序设计”和“本日增量”说明；教学伪代码与可运行示例明确区分，不宣称未经运行的代码已验证。

示例属于同一个逐步演进的 Agent Runtime 设计。前序章节既有结构为起点；独立验收仅表示不依赖实际工程完成状态，不表示每天建立互不兼容的工程。Eino 作为源码对照，不直接替换课程已有接口；差异通过适配层或明确迁移解释。


## 可运行示例基线（examples）

生成前必须读取 `examples/README.md`、`examples/CONTRACTS.md` 及当天涉及的 `examples/internal` 示例代码。课程选题仍由既定路线决定，不扫描根目录 `internal` 的学习者实现来判断进度。所有可运行课程示例共享根 go.mod，在 examples 中累计演进；不建立每日独立 module。页面中的建议文件路径使用 examples 前缀，并区分新增、修改、复用，列明承接关系、验收及迁移。后续课程在授权范围内可同步增量更新 examples 和契约文档，不修改根目录 internal/cmd 学习者代码；与当天 HTML、index.html 一起提交，未运行的验收必须标记未执行。更新前核对 main 最新 SHA，保留其他改动。具体结构、错误语义和数据流以 examples/CONTRACTS.md 为准。

今天只解决什么

今天实现共享 Sink 的串行包装，让多个执行者能够安全地写入同一个普通接收器。

两个 Agent 同时把事件 append 到同一个切片，会发生数据竞争。仅保证每个 Agent 内同步，并不保证跨 Agent 的接收器安全。

只同步一个包装器的 Emit；不增加 Agent 运行并发承诺、不保护模型或工具、不做异步队列、取消抢占或死锁检测。

先解释概念，再看一次具体运行

共享接收器

是什么：多个执行者使用的同一个观察对象。

为什么需要：32个调用者各发布10个读取阶段事件。

落到代码：底层 unsafeSink 的计数必须为320。

串行包装

是什么：每次只允许一个调用进入底层方法。

为什么需要：等待者持有自己的 ctx 与 Event，轮到后原样转发。

落到代码：SynchronizedSink 的互斥锁只包围 Emit。

取消后的观察

是什么：停止业务不代表丢弃终止信息。

为什么需要：已经取消仍发布 run_failed/cancelled。

落到代码：包装器不按 ctx.Err 丢弃事件。

失败反例

如果有人绕过包装器直接访问 raw，或同一个 raw 被两个不同包装器保护，仍可能竞争。底层 Emit 重入同一包装器会死锁；慢 Sink 也会阻塞所有等待者。

为什么这样设计

SynchronizedSink / NewSynchronizedSink

职责与字段/参数：内部 mu 保护整次转发；sink 保存调用方提供的 EventSink。NewSynchronizedSink(s) 返回非 nil 指针，s 可 nil。

返回与失败：构造无错误、无下游调用；nil sink 的 Emit 安全返回。

状态、所有权与取消：包装器开始使用后不得复制；所有下游访问必须走同一个包装器。零值也可当禁用接收器。

设计理由：锁属于共享资源的唯一入口，比每个 Agent 各加一把锁有效。

Emit

职责与字段/参数：Emit(ctx,e) 等待互斥锁后，把同一个 ctx 与按值复制的 Event 交给下游，返回后解锁。

返回与失败：没有返回值，不吞 panic；取消不丢事件，不修改 At、Status 或 Step。

状态、所有权与取消：互斥锁等待不响应 context 取消；下游要快速返回，不得重入。不同发布者之间无排序保证；同一 goroutine 的顺序保留。

设计理由：同步包装只保证互斥，不是假装已实现异步可观测平台。

取消边界与复用

职责与字段/参数：Day04–05 的 Run 负责取消业务和唯一终态；本日不改 Run、不覆盖前序算法。

返回与失败：race 测试刻意使用没有锁的下游，检查计数、ctx 和 Event，断言只看公开行为。

状态、所有权与取消：脚本 Mock 有游标，不并发共享；这组测试不证明 Agent 或真实后端并发安全。

设计理由：明确每个层次的并发责任，避免局部通过被扩大解释。

package agent_test

import (
	"context"
	"github.com/linko-zhao/mini-agent-runtime/internal/agent"
	"sync"
	"testing"
)

type unsafeSink struct {
	count int
	ctx   context.Context
	last  agent.Event
}

func (s *unsafeSink) Emit(c context.Context, e agent.Event) { s.count++; s.ctx = c; s.last = e }
func TestDay06SharedSink(t *testing.T) {
	raw := &unsafeSink{}
	sink := agent.NewSynchronizedSink(raw)
	var wg sync.WaitGroup
	ctx := context.WithValue(context.Background(), struct{}{}, "trace")
	ev := agent.Event{Type: agent.EventRunStarted, Step: 1, Status: "ok"}
	for i := 0; i < 32; i++ {
		wg.Add(1)
		go func() {
			defer wg.Done()
			for j := 0; j < 10; j++ {
				sink.Emit(ctx, ev)
			}
		}()
	}
	wg.Wait()
	if raw.count != 320 || raw.ctx != ctx || raw.last != ev {
		t.Fatal(raw.count)
	}
}
func TestDay06NilAndCancelled(t *testing.T) {
	agent.NewSynchronizedSink(nil).Emit(context.Background(), agent.Event{})
	raw := &unsafeSink{}
	sink := agent.NewSynchronizedSink(raw)
	ctx, cancel := context.WithCancel(context.Background())
	cancel()
	sink.Emit(ctx, agent.Event{Type: agent.EventRunFailed, Status: "cancelled"})
	if raw.count != 1 || raw.ctx != ctx || raw.last.Status != "cancelled" {
		t.Fatal(raw)
	}
}

package agent

import (
	"context"
	"sync"
)

// SynchronizedSink 可被多个 Agent 共享；所有调用必须经同一个包装器。
// 下游不得重入此包装器，否则会死锁。
type SynchronizedSink struct {
	mu   sync.Mutex
	sink EventSink
}

func NewSynchronizedSink(s EventSink) *SynchronizedSink { return &SynchronizedSink{sink: s} }
func (s *SynchronizedSink) Emit(ctx context.Context, e Event) {
	s.mu.Lock()
	defer s.mu.Unlock()
	if s.sink != nil {
		s.sink.Emit(ctx, e)
	}
}

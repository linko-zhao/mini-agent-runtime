任务 B · 定义核心数据结构与接口（25 分钟）

在 internal/model/model.go 定义模型无关的数据类型，使用 context.Context 传递取消与超时，使用 json.RawMessage 保留原始工具参数：

type Message struct {
    Role       string
    Content    string
    ToolCalls  []ToolCall
    ToolCallID string
}

type ToolCall struct {
    ID        string
    Name      string
    Arguments json.RawMessage
}

type Response struct { Message Message }

type Model interface {
    Generate(ctx context.Context, messages []Message) (*Response, error)
}

在 internal/tool/tool.go 定义：

type Tool interface {
    Name() string
    Execute(ctx context.Context, args json.RawMessage) (string, error)
}

注意各文件必须补全 package / import，示例仅展示接口核心。

任务 C · 实现 Agent Loop（35 分钟）

在 internal/agent/agent.go 实现 Agent.Run(ctx, input) (string, error)；Agent 至少维护 model.Model、map[string]tool.Tool、maxSteps。

  1. 创建初始用户消息，调用 Model.Generate。
  2. 先把模型返回的 Assistant 消息（含 ToolCalls）加入历史。
  3. 没有工具调用时返回最终文本；否则按顺序执行每个 ToolCall。
  4. 将工具结果作为 Role=tool 的消息写入历史，保留 ToolCallID。
  5. 继续调用模型直到完成或达到 maxSteps；每轮调用前检查 ctx.Err()。
  6. 未知工具、模型错误与超时应返回可判断的错误，不要忽略。

任务 D · 实现 Mock Model（10 分钟）

在 internal/model/mock.go 使用预设 Response 序列模拟两轮：第一轮模型要求执行 calculator，第二轮返回“计算结果为 2”。在 cmd/demo/main.go 中使用 Mock Tool 验证完整流程。Mock Model 不需要 API Key。

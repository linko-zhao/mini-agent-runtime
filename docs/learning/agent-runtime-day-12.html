Day 12 / 56 · MCP 生命周期与工具协议

本地工具接口之外，怎样发现和调用另一个进程或服务提供的能力？先弄清协议会话，再设计 Agent 适配。

为什么现在需要 MCP？

能解释 Host、Client、Server 的职责，画出 initialize → initialized → tools/list → tools/call 的过程，并区分能力声明、执行授权、协议错误和工具执行结果。

前几天已经把工具描述、调用调度、超时重试和执行授权分层。若另一个团队提供文档服务，直接共享它的 Go 对象无法跨进程；每个后端各定义一套发现和调用 API，又会增加适配成本。MCP（Model Context Protocol）为宿主与能力服务提供约定的会话和消息格式。

Host 是管理用户会话与 Agent 的应用；它为 Server 建立 MCP Client。模型并非直接发送 MCP 报文的网络客户端，仍然只提出工具调用意图。Server 发布描述并执行请求，具体业务权限也仍由服务端决定。

今天只完成协议会话层。参考实现发送真实 JSON-RPC JSON，使用内存传输复用已有 GetDocument；Day 13 再把它适配成既有 Meta/Invoke 工具。不要把演示输出文档等同于已接入真实 MCP 网络服务或真实模型。

先走通完整数据流，标出今天的位置

完整 Agent 目标：
Host 认证用户 → Agent.Run → Model.Generate → ToolCall
 → Day11 本地授权 → Day10 执行策略
 → [Day13 MCP工具适配器] → MCP Client → Server → 后端
 ← 工具结果 → 保留原 ToolCallID 的 tool 消息 → 下一轮 Model

今天实际运行：
Host 创建 Client(Transport) 和离线 DemoServer(GetDocument)
 → initialize(协议版本、客户端信息、客户端能力)
 ← 初始化结果(服务器版本、信息、服务器能力)
 → notifications/initialized（通知，无ID，无响应）
 → tools/list(cursor) ← 描述列表与可选nextCursor
 → tools/call(name,arguments) ← content、isError、可选structuredContent

装配阶段建立连接和协商，并发现元信息；运行阶段执行具体工具请求。初始化前不能查询工具。服务器声明 tools 能力后才能使用相关方法；发现到工具仍不等于当前用户获得权限。

先预测：服务端接收到了调用，但响应丢失。这时客户端不能简单重发：原操作可能已经发生。本课将传输或协议不确定后的会话标为 failed，不自动重放；真正重连、会话恢复和业务幂等需另行设计。

三个容易混淆的“版本/ID”

字段用途本课约定
jsonrpc = 2.0消息信封格式请求和响应均检查；不是MCP版本
protocolVersion = 2025-06-18MCP协议版本协商固定教学版本；服务器返回其他版本则拒绝，不声称使用最新版
JSON-RPC request ID协议请求/响应配对Client分配递增整数；通知没有ID
model.ToolCall.ID模型请求与tool消息配对保持原课程结构；不能拿协议ID替换它，Day13负责跨边界关联

示意请求均对应本日实现的真实字段。以下 tools/call 信封可在传输测试中观察：

{"jsonrpc":"2.0","id":3,"method":"tools/call",
 "params":{"name":"get_document","arguments":{"id":"doc-1"}}}

{"jsonrpc":"2.0","id":3,"result":{
 "content":[{"type":"text","text":"工具返回的文档内容"}],
 "isError":false}}

result 与 error 只能有一个。工具执行失败可以是合法 result，带 isError=true；它与 JSON-RPC error 不同。不要把所有失败都压成一个字符串再决定重试。

四个设计选择及代价

选择为什么这样做还没有解决什么
先协商再操作避免在未知版本/能力下发送调用；initialized通知完成后才ready没有完整服务端主动消息、动态能力刷新和版本降级
工具能力与权限分开tools表示协议功能；本地调用者权限仍由Day11检查本课不是OAuth或资源ACL实现；远端readOnlyHint也不是安全重试证明
保留结果内容块避免把image/resource等内容静默丢掉；保留structuredContent供后续适配只检查基本形状，不做完整多模态/schema校验；Day13需明确支持或拒绝哪些类型
固定内存传输、会话内串行先验证消息和状态，不把端口、进程和SDK配置混进协议学习没有真实stdio/Streamable HTTP、并发多路复用、HTTP会话头或传输资源管理

stdio 与 Streamable HTTP 是传输方案，报文方法相同但分帧、生命周期与鉴权不同。本课 Transport.Send 接收完整JSON并返回完整响应；它不是完整网络协议栈。真实工程优先使用成熟SDK。

内存示例没有要关闭的进程或连接；真实连接结束由传输资源清理完成，不要从其他协议照搬一个不存在的 MCP shutdown RPC。固定1MiB响应预算在Send返回后检查，只限制后续解析，真实传输仍需独立的缓冲区/帧大小限制。

四项连续演进练习：先设计，再对照参考

任务一 · 20分钟：定义Host/Client/Server与协议端口

为什么做：避免把“模型调用工具”和“网络发送协议”混成一个接口。操作与观察：5分钟手画完整Agent路径；10分钟阅读types.go并标出哪些是线协议、哪些继续复用Runtime；5分钟区分以下方法和前序Invoke。以下是参考接口摘录，不是独立程序：

type Transport interface {
    Send(context.Context, []byte) ([]byte, error)
}
func NewClient(t Transport) (*Client, error)
func (c *Client) Initialize(ctx context.Context) (InitializeResult, error)
func (c *Client) ListTools(ctx context.Context, cursor string) (ToolsPage, error)
func (c *Client) CallTool(ctx context.Context, name string,
    args json.RawMessage) (ToolResult, error)

完成证据：能解释为什么保留一套线协议Descriptor并不意味着替换原tool.Spec；指出ModelToolCallID和JSON-RPC ID分别在哪里生成、消费。

任务二 · 25分钟：跟踪初始化和会话失效

为什么做：一个可用连接不等于一个完成协商的会话。操作与观察：10分钟预测未初始化list、版本不匹配、初始化通知失败；10分钟沿client.go中的new → ready/failed与请求门控追踪；5分钟解释错误后为什么不自动重试。初始化result需要版本、能力与ServerInfo，initialized通知不能收到响应。

完成证据：生命周期测试观察到initialize、无ID通知、list、call的顺序；版本/通知失败后不重放初始化；排队取消不发送请求。传输忽略context时，本层也不能强制终止它。

任务三 · 20分钟：发现一页工具，区分三种失败

为什么做：协议边界必须保留足够信息，后续Agent才能选择恢复还是终止。操作与观察：10分钟跟踪ListTools的tools和nextCursor、CallTool的content/structuredContent/isError；10分钟先预测再运行未知工具、缺失文档、响应ID错误和响应丢失的测试。

情况本课返回与会话
缺失文档等业务失败ToolResult.IsError=true，Go error为nil，保留内容块，待Day13安全映射
有效JSON-RPC error返回*RPCError，可errors.As识别；会话仍可用，Error()不直接输出远端Message/Data
传输/取消或畸形协议响应保留错误链；已发送请求可能被执行，会话failed，不自动重放

完成证据：游标是不透明字符串；客户端只请求一页，不会隐式反复翻页。非文本内容未丢失；descriptor和result shape被检查，但完整schema与业务校验仍由服务端/成熟SDK负责。

任务四 · 15分钟：运行既有知识工具的协议往返

Definition of Done 与 Day 13 衔接

理解上：能手画会话生命周期、区分能力和权限、区分三个错误层次，并说明两个ID域为何不能混用。实现上：初始化顺序、ID匹配、拒绝畸形消息、取消与内容保留有测试，累计examples与race通过。本次参考示例已完成这些验证；完整网络SDK不属于本日交付。

Day13将Descriptor映射到既有Spec，将CallTool接到Invoke，再经过Registry、WithPolicy、WithAuthorizer接回模型工具往返。重点是复用前序契约、处理名称冲突与错误/内容映射，不复制业务工具；发现到远端能力仍不意味着获得执行授权。

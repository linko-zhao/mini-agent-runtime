## 问题与改进建议

| 优先级 | 问题、影响与证据 | 验收条件 |
| --- | --- | --- |
| P0 | `internal/agent/agent.go` 工具子 context 超时后返回父 `ctx.Err()`；父 context 未取消时可能返回 `("", nil)`，将超时报告为成功。`Generate` 返回 `nil, nil` 时访问 `r.Message` 会 panic。 | 对子超时保留 `context.DeadlineExceeded` 错误链；空响应返回明确错误和唯一失败终态，分别补充测试。 |
| P1 | `defer cancel()` 在循环中延迟释放；工具超时固定 300 秒，超时路径缺少 `ToolCompleted`。最终文本和模型错误路径没有 `StepFinished`；事件契约及取消状态未明确。 | 每次工具执行后立即释放 context，定义超时配置及事件顺序和终态；测试超时、取消、空响应和各结束路径。 |
| P1 | 同一个 Agent 的 sink 回调由其 mutex 串行化，但不同 Agent 共享同一 Sink 时锁不共享；同步回调阻塞或重入也可能阻塞运行。当前测试的收集器自身有锁，不能证明所有 Sink 安全。 | 在 `docs/design.md` 说明同步、并发和重入契约；针对实际支持的共享方式补充并发测试，避免宣称全局串行。 |
| P1 | Adapter 未限制响应大小、未验证缺失工具名或非法工具参数；绑定未检查名称一致。 | 有界读取、验证协议数据及注册名，补充离线异常测试；记录工具错误回填策略。 |
| P2 | Calculator 的 JSON 解码未落实 schema 中必填与额外字段约束。 | 第二周补工具注册与参数校验，并测试缺失、额外和非法参数，再推进 MCP。 |

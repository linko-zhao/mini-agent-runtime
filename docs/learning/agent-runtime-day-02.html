任务 A · 15 分钟扩展模型响应与错误类型

修改 internal/model/model.go，保留 Day 01 的 Message、ToolCall 和 Model 接口；为 Response 补充完成原因和用量，新增可分类的 ModelError。

type FinishReason string // 模型本轮结束原因；保留未知值便于兼容
const (
    FinishStop      FinishReason = "stop"       // 正常结束
    FinishToolCalls FinishReason = "tool_calls" // 请求执行工具
    FinishLength    FinishReason = "length"     // 达到输出长度限制
)

type Usage struct {
    InputTokens  int // 本轮输入 token 数
    OutputTokens int // 本轮输出 token 数
}

type Response struct {
    Message      Message      // 归一化的 assistant 消息
    FinishReason FinishReason // 模型结束原因
    Usage        Usage        // 本轮 token 用量；缺失时为零值
}

type ModelError struct {
    StatusCode int  // HTTP 状态码；传输错误可为 0
    Code       string // 分类码，如 unauthorized、rate_limited
    Retryable  bool // 是否适合上层考虑重试（非自动重试）
    Err        error // 原始错误；实现 Unwrap() 支持 errors.As/Is
}

设计取舍：保留 Generate(ctx, messages) 的原始签名，避免改动 Day 01 Agent Loop。今天先实现非流式调用；工具定义的注册与模型绑定安排在后续工具系统阶段。模型返回 ToolCall 的解析仍要完成。

任务 C · 20 分钟规范化 ToolCall 与异常

创建 internal/model/openai/convert.go（也可拆出 error.go），实现以下转换规则：

正常响应

文本直接进入 Message.Content；多个工具调用逐一转换，保留 ID、Name 和原始 JSON 参数；工具调用消息角色保持 assistant。

异常响应

空 choices、缺失工具名称、非法 JSON 参数返回可判断错误；401 为鉴权错误，429 为限流错误，5xx 可标记为可重试；ctx 取消原样保留错误链。

注意：Retryable 只是错误属性，不代表今天应实现自动重试。重试需要在未来考虑副作用、次数上限和退避策略。
